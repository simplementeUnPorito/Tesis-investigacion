## Contexto del día

Hasta el 30 de junio todo el proyecto vivía en un único repositorio Git con miles de archivos binarios de PSoC Creator, datos de MATLAB, scripts Python y documentación mezclados en el mismo árbol y el mismo historial — cada build de firmware generaba decenas de miles de líneas de diff en objetos y listados que no tenían nada que ver entre sí, y el repo se había vuelto pesado y difícil de razonar. El 21 de julio es el día en que ese modelo se abandona. El commit raíz del nuevo `main` lo explica en su propio mensaje:

> "chore: initialize the modular thesis superproject — The monolithic repository is preserved privately in Tesis-legacy. This root commit pins the independently versioned firmware, software, modeling, documentation, research, and data repositories."

Es un commit sin padres (`git cat-file -p` confirma que no tiene ningún `parent`): el nuevo `main` no es un rebase ni un filter-branch del histórico anterior, es un árbol nuevo que apunta, vía `.gitmodules`, a siete repositorios de GitHub separados (`Tesis-firmware-psoc`, `Tesis-firmware-esp32`, `Tesis-software-python`, `Tesis-modelado-matlab`, `Tesis-investigacion`, `Tesis-datos`, `Tesis-documentacion`), cada uno con su propio historial reconstruido a partir del contenido correspondiente del monolito original. La bitácora, sin embargo, sigue viviendo en la rama local `bitacora/recovery` de este mismo repo `Tesis` — un detalle importante: la documentación del proceso de tesis no se modularizó junto con el código.

Dos cambios de hardware significativos escondidos en dos líneas: primero, un renombre semántico de `PGAshield` a `PGAout` — sugiere que el rol de ese bloque de PGA se reinterpretó (de "blindaje"/protección a "salida" de la etapa) tras entender mejor la topología real medida en el modelo de circuito (ver más abajo el trabajo de MATLAB del mismo día, que trata justamente sobre el modelo del PGA→ADC). Segundo, y más importante: **`LPF_2_Start()` estaba comentado** — es decir, la segunda etapa de filtro pasabajos del hardware nunca se activaba en el firmware — y ese día se descomenta. Esto es el tipo de bug de "una línea comentada que nadie recordó reactivar" que puede explicar semanas de comportamiento de filtrado subóptimo sin que nada falle de forma obvia (el sistema seguía funcionando, solo con menos atenuación de la esperada).

El resto del diff de este commit (`+15.534/-12.112` en 37 archivos) es en gran parte el `TopDesign` regenerando código fuente para cuatro bloques `Amux` nuevos: `BP_Amux`, `LP_Amux`, `PGAin_Amux`, `SUM_Amux` — un multiplexor analógico dedicado por etapa (Band-Pass, Low-Pass, entrada de PGA, sumador), en vez de compartir un único AMux general entre todas. Esto es consistente con el pedido de julio de tener rutas de calibración más limpias por etapa: cada etapa puede ahora seleccionar su propia entrada/referencia sin depender de un mux central compartido con las demás.

### `a3d87e3` (MATLAB) — "XD" — 21:03 hs — el modelo de circuito madura

#### Diff y análisis técnico

Este es el commit de mayor densidad de análisis técnico del día. `analizar_sweeps_circuito.m` crece +707 líneas y el `README.md` de `AnalisisCircuito` documenta varios avances de modelado importantes:

**1. El modelo del operacional se simplifica a una sola referencia.** Antes se comparaban tres curvas (ideal, PSoC High GBW=8MHz, variante conservadora GBW=3MHz); ahora solo se grafica el modelo PSoC High con los componentes actuales — señal de que el modelo ya está lo suficientemente validado como para no necesitar mostrar el rango de incertidumbre completo en cada gráfico.

**2. El compensador se recalibra para `Ru=6.8 kOhm` en vez de `7.5 kOhm`**, cambio de valor de componente real medido en el hardware:

```
CH3/PGA = (-27k/6.8k) * (s² + 2·zeta0·w0·s + w0²)/(s² + 2·zeta1·w0·s + w0²) * 1/(1 + s·27k·15n)
```

Con `Ru=6.8 kOhm`, el `Rbp` total requerido para lograr `zeta0=0.25` es `≈7434.54 Ohm`: los `6.8 kOhm` fijos más aproximadamente `634.54 Ohm` de un potenciómetro. El texto detalla que el nulo del potenciómetro está cerca de `632.56 Ohm` y hay que aumentar unos `1.98 Ohm` desde ahí — la clase de precisión que solo tiene sentido cuando ya se está calibrando contra medición real, no contra valores nominales de datasheet.

**3. Manejo inteligente de saturación por tramos, no por captura completa.** Antes, si un canal saturaba durante el sweep, toda la captura se descartaba para esa etapa. El nuevo código "amplía cada recorte un ciclo local a ambos lados, busca los intervalos lineales continuos restantes y los incorpora como submuestras independientes de la FRF" — en vez de tirar la captura entera, se recupera la porción de espectro donde el canal seguía siendo lineal. Esto es una mejora real de eficiencia de datos: cada sweep de banco es costoso de tomar, y descartarlo completo por saturar en un extremo de frecuencia desperdiciaba la información válida del resto de la banda.

**4. Nuevo criterio de tolerancia Monte Carlo con barrido del potenciómetro.** La envolvente azul (4000 realizaciones con tolerancias de componentes ±1%/±20%/±40% según tipo) se complementa con una envolvente naranja que además barre 41 posiciones del recorrido eléctrico completo del potenciómetro. La lectura práctica: "una medición fuera de la azul pero dentro de la naranja puede ser compatible con componentes válidos y un cursor mal calibrado; fuera de ambas apunta a otra discrepancia". Es una forma de distinguir error de calibración de cursor vs. error real de modelo o montaje — diagnóstico más fino que antes.

**5. Nueva función auxiliar `verificar_calibracion_potenciometro`** para detectar si una campaña de mediciones mezcló accidentalmente posiciones distintas del cursor del potenciómetro entre capturas, con un criterio de confiabilidad explícito (mínimo 8 puntos, residuo complejo relativo ≤0.35).
