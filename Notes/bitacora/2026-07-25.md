En Unix, un pipe tiene un buffer limitado (típicamente 64 KB). Si el proceso hijo escribe a stdout más rápido de lo que el padre lee, el hijo se bloquea en el `write()` del kernel apenas se llena el buffer — y como el servidor bajo prueba imprime una línea por cada POST recibido, bastaban unas pocas decenas de requests en tanda para llenarlo y colgar al servidor entero, no solo al logging.

Eso es la firma típica de un problema de "vecino ruidoso": el bug no está en el check que falla, está en el orden de ejecución y en cuánta salida generaron los checks anteriores. Se necesitó abandonar la hipótesis de "el refactor tiene un bug de concurrencia" para llegar a la verdadera causa raíz: la infraestructura de test se ahogaba a sí misma.

Esa última frase — "nada de esto puede correr en el event loop" — es una decisión de arquitectura async importante: el procesamiento numérico (decimado min/max sobre arrays potencialmente grandes) es trabajo de CPU, y si corriera dentro de una corutina `async def` bloquearía el event loop de FastAPI, congelando todas las demás requests concurrentes. El corazón técnico del commit es la función `decimate_minmax`, que resuelve un problema real de visualización de señales de alta frecuencia: un shot de geófono puede tener decenas de miles de muestras, mucho más de lo que tiene sentido dibujar en un canvas de unos cientos de píxeles de ancho. El comentario explica por qué se eligió decimado min/max en vez de promediado o submuestreo simple:

```python
def decimate_minmax(x: np.ndarray, max_points: int) -> tuple[np.ndarray, np.ndarray, int]:
    """Envolvente min/max por bucket. Devuelve ``(mins, maxs, stride)``.

    Por qué min/max y no un promedio ni un salteado: el primer arribo es un
    pico de pocas muestras. Promediar lo suaviza hasta hacerlo invisible y
    saltear se lo come cuando el pico cae entre dos muestras elegidas. Con
    min/max, cada píxel dibuja el rango real que hay abajo: la envolvente
    pasa exactamente por los extremos de la señal completa.
    """
    n = int(x.size)
    if n == 0:
        empty = np.array([], dtype=np.float32)
        return empty, empty, 1
    x = x.astype(np.float32, copy=False)
    stride = max(1, -(-n // max_points))        # ceil(n / max_points)
    nb = -(-n // stride)                        # ceil(n / stride)  <= max_points
    pad = nb * stride - n
    if pad:
        x = np.concatenate([x, np.full(pad, np.nan, dtype=np.float32)])
    m = x.reshape(nb, stride)
    with warnings.catch_warnings():             # buckets all-NaN avisan y devuelven NaN
        warnings.simplefilter("ignore", RuntimeWarning)
        mins, maxs = np.nanmin(m, axis=1), np.nanmax(m, axis=1)
    return mins, maxs, stride
```

La razón técnica es específica del dominio del proyecto: en MASW, el "primer arribo" (first break) de la onda es exactamente el tipo de evento breve y de amplitud alta que un promedio por bucket destruye — si un pico de 3 muestras cae en un bucket de 50 muestras promediadas, su contribución al promedio es casi nula y desaparece visualmente. Un submuestreo (tomar 1 de cada N) es aún peor: si el pico no cae justo en la muestra elegida, se pierde por completo. El decimado min/max, en cambio, garantiza que cualquier extremo local dentro de cada bucket — sea un pico de first arrival o un valor atípico de ruido — quede representado en la envolvente, sin importar en qué posición exacta del bucket caiga.

La implementación usa el truco de `-(-n // stride)` para calcular `ceil` con aritmética entera sin usar `math.ceil` (equivalente a `-(-n // stride) == math.ceil(n / stride)` para enteros positivos), rellena con `NaN` el resto del último bucket si `n` no es múltiplo exacto de `stride`, y usa `nanmin`/`nanmax` para que ese padding no contamine el resultado — silenciando a propósito el `RuntimeWarning` que numpy emite cuando un bucket queda completamente en `NaN` (algo que, dado el padding, solo puede pasar en el último bucket si `pad == stride`, caso límite ya contemplado).

Otro detalle cuidado es el redondeo de valores para el JSON de salida:

```python
def _round6(v: float) -> float | None:
    """6 cifras significativas; no-finito -> ``None`` (nunca ``NaN`` en el JSON)."""
    v = float(v)
    if not math.isfinite(v):
        return None
    return float(f"{v:.6g}")
```

El estándar JSON no tiene representación para `NaN` o `Infinity` (a diferencia de JavaScript, que sí los admite como valores especiales pero no como JSON válido); serializar un `NaN` directamente con algunas librerías produce el literal no estándar `NaN` en el texto, que rompe el parseo en clientes estrictos. Convertirlo a `None` (que se serializa como `null`) es la forma correcta de comunicar "sin valor" de forma portable.
